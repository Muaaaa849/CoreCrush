# ネットコード規則（GDD 11章）

## 方式: 受け手権威
- ボールが自陣へ向かっている間は、受け手が軌道・キャッチ・跳ね返し・被弾・爆発を判定する。
- 返球（跳ね返し・投擲）した時点で権威は相手へ移る。権威の所在は常に1か所。
- 投げた側は投擲イベント（開始フレーム、球種、速度倍率、投擲時カウント、スキル効果）を送る。
  受け手はそこから決定論的にボールを生成する。
- **遅延は「発射点から再生」で吸収し、飛翔時間は削らない**（受け手の反応時間を縮めない）。
- 自分の移動は即時反映（予測）、相手の移動は補間表示（初期値 100ms、data で管理）。
- 判定コードは `src/sim/judge/` に置き、net 層は「イベントの運搬と権威の受け渡し」だけにする。

## DataChannel
- `state`: 非信頼（`ordered:false, maxRetransmits:0`）。60Hz の入力と位置。直近4フレームを冗長同梱。
- `event`: 信頼（既定設定）。投擲・キャッチ・跳ね返し・スキル・被弾・爆発・ラウンド遷移。
  全イベントにフレーム番号と単調増加の連番を付ける。
- メッセージ形式はバイナリ（DataView）で固定レイアウト。スキーマ変更時はプロトコル版数を上げる。

## 決定論
- sim は固定60Hz。`Math.random`・`Date`・`performance.now` を判定に使わない（シード付き RNG と tick のみ）。
- 同じ入力列の再生で、両クライアントの確定イベントログ（種類・確定フレーム・結果）が一致すること。

## 接続・秘密
- STUN: `stun.cloudflare.com`。TURN は Worker が短命の資格情報を発行する。
- TURN の API トークンは Worker の secret のみ。クライアント・リポジトリに置かない。
- シグナリングは部屋コード1つ＝Durable Object 1つ。WebSocket で SDP/ICE を中継するだけ。

## テスト（必須）
- 遅延注入マトリクス: RTT 0/80/160ms × ロス 0/2/5%。
  - 確定イベントログのハッシュ一致。
  - 「フリ→ストレート」成立率が遅延0時の ±5% 以内。
- 遅延注入は net 層の差し替え可能なトランスポートで行い、実ネットワークに依存しない。
- 不正対策はしない（カジュアル P2P 前提）。ただし受け手申告の値域チェックは入れる。
