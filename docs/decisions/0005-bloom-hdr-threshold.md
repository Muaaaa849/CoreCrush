# 0005 ブルームは HDR 色のしきい値で掛ける（MRT の emissive 分離は採らない）

## 背景
- GDD 12.2・M3 計画: 「emissive ベースの選択的ブルーム。しきい値高めでネオン・コア・フェンスだけ光らせる」。計画では MRT で emissive を別バッファに出してブルームする想定だった（M0 ベンチと同じ構成）。
- 実装して確かめたところ（three r186、WebGL2 バックエンド）、MRT の emissive バッファには**アルファブレンドが効かず、半透明の物が後ろの emissive を上書きする**。
  α を 0 にしても上書きされた。結果として:
  - コート中央のプラズマ・フェンス（不透明度 0.07）越しに見る相手コートのコアが**光らなくなる**。
  - TPS で半透明にしている自分の体の向こうのコアも光らない。
  → 「コアを常に画面で最も明るい物体に」（可読性の不変条件）を壊す。

## 決定
- ブルームはシーンパスの**トーンマップ前の HDR 色**（HalfFloat）に、しきい値 `data/render.json` の `bloom.threshold`（1.0）で掛ける。
  照明を受けた普通の面は輝度 1 未満、emissive を強くした物（コア 3.0 など）だけがしきい値を超える。
- 半透明の物は色バッファで通常どおり合成されるので、フェンスや自分越しのコアも光る。
- MRT を使わないので、描画先が 1 枚減る（スマホの帯域に有利）。
- 調整用に `?post=glow`（ブルームだけを表示）。

## 代替案
- MRT の emissive 分離（計画どおり）: 上のとおり半透明で壊れる。半透明の物だけ別パスで描いて深度を共有する方法はあるが、パスが増えて重い。
- 半透明の物に emissive を持たせない: 上書き自体は止まらない（0 で上書きされる）。
- WebGPU の添付ごとの書き込みマスク: three から指定できず、WebGL2 フォールバックでも使えない。

## 不変条件への影響
- コアの可読性: 改善（半透明越しでも光る）。
- 注意: 明るい照明の反射（濡れた床の鏡面ハイライトなど）もしきい値を超えれば光る。ネオンの映り込みとしては望ましいが、
  **コアより明るい物を作らない**ように、ステージの照明・emissive はしきい値との関係で決める（手順3・4 で確認）。

## 撤回条件
- ステージを作って、光らせたくない物がしきい値を超えて抑えられないとき。
- three が MRT 添付のブレンド・書き込みマスクに対応し、半透明で上書きされなくなったとき（MRT 方式に戻せる）。
