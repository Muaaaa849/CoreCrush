# 0006 アセットの変換（KTX2）と、床・遠景の作り方

## 背景
- プランナーのプレイテスト（2026-09-30）: 「床もフェンスももっと上手く作れる。GDD を確認して」。GDD 12.2 は「HDRI＋PBR、濡れた路面は粗さムラでネオンを映す」、render 規則は「テクスチャは全て KTX2」。
- 遠景はプランナーが Nano Banana 2 で生成した 3 枚（夜空・サイバー街・スチーム工場。街の 2 枚は緑のクロマキー背景）。
- クラウド環境に toktx・basisu・ImageMagick が無い。

## 決定
- **変換は npm だけで完結させる**: `sharp`（縮小・クロマキー）＋ `ktx2-encoder`（basis_universal の wasm）。`npm run assets` が `art/assets.json` の一覧を
  取得 → 切り抜き → 4 の倍数に縮小 → KTX2（色 = ETC1S sRGB、法線 = UASTC、粗さ = ETC1S 線形、ミップマップあり）にして `assets/textures/` に出す。
  元画像（`art/source/`・`art/generated/`）と出力を両方コミットする（CI で再変換しない）。
- 実行時は `KTX2Loader`。トランスコーダーは `scripts/proto-pages.mjs` がページの隣の `basis/` に置く。読めない環境（単一ファイルの Artifact 版）は手続き的な見た目のまま動く。
  単一ファイル化で `import.meta.url` が無くなるので、ビルドで `document.baseURI` に置き換える（KTX2Loader が読み込み時に URL を組むため）。
- 床: CC0 のアスファルト（Poly Haven asphalt_02、1K）。ノイズで水たまり（粗さ低・法線平ら・暗く）。
  **高画質だけ平面反射（ReflectorNode・半解像度）**を水たまりに強く・乾いた所に弱く足す（`quality.json` の `floorReflection`）。中・低は環境マップだけ。
- 遠景: 夜空は円筒（3 回鏡映し）、街は切り抜いた板を 2 層の輪に並べる（InstancedMesh 各 1 回）。距離の霧の外なので霧を掛けず、自前で暗く・彩度を落とす。

## 代替案
- 画像を PNG/WebP のまま使う: 規則（KTX2・VRAM 予算）に反する。
- SSR（画面空間反射）: 画面外が映らず、ポストのコストが大きい。平面の床には平面反射が確実で安い。
- 遠景を 3D の箱で作る（第 1 版）: 物足りない、という評価。生成画像のほうが世界観の参考に近い。

## 不変条件への影響
- コアの可読性: 反射にもコアが映るが、背景・床はブルームのしきい値未満（スキーマで検査）。持った球は heldDim で暗くする（別コミット）。
- 性能: 平面反射はシーンをもう一度半解像度で描くので、高画質だけ。ドローコールは遠景 3・床 1。手順6 で計測する。

## 撤回条件
- 高画質で平面反射がポスト込みの予算（GDD 12.3）を超える → 解像度を下げるか、中と同じ環境マップだけにする。
- ktx2-encoder の出力が特定端末で読めない → basisu の CLI を CI に入れて作り直す。
